# Legacy labels and revenue — v1 project policy

The 13 groups and the condition **business credit with no excluding group** come from [Fundo's challenge](../CHALLENGE.md). The exact keywords, literal-substring matching, precedence, personal markers, and exclusion set are **our approved v1 choices** in [BUSINESS_RULES.md](../archive/rules/BUSINESS_RULES.md), not Fundo policy or verified financial facts. Implementations are `src/fundo_reviewer/legacy.py` (`legacy-v1`) and `src/fundo_reviewer/revenue.py` (`revenue-v1`). Changing either policy requires a version bump and new tests/reports.

For each posted, accepted transaction, search `name` and optional `merchant_name` independently after Unicode NFKC normalization, casefolding, and whitespace collapse. Preserve punctuation and do literal substring matching. Do not inspect Plaid categories, account metadata beyond the accepted transaction, synthetic truth, or model output. Retain original source fields and trace every matching keyword rule ID, keyword, field and precedence rank. The first matched group in the [approved priority order](../archive/rules/BUSINESS_RULES.md#3-legacy-labels-and-revenue) wins. With no group matches, return `unmatched` (not a fourteenth Fundo group). Stable rule IDs and source-independent label ordering make runs reproducible.

The personal markers are `personal`, `owner draw`, `owner contribution`, `family transfer`, and `household`. Any marker in either searched field gives `personal`; otherwise **default `business`**. This fallback is intentionally weak and will misclassify unmarked owner activity. Marker hits are traced separately from group hits.

Code derives revenue **only** when the original Plaid `amount` is negative, status is `business`, and the winning group is not one of `Not average monthly revenue`, `NSFs`, `Overdraft`, `Internal transfer`, `UCC`, `Active advance`, or the five `High risk` groups. `Auto deposit`, `Revenue verification`, and `unmatched` do **not** exclude a business credit by name alone. Positive amounts and personal credits are never revenue. Funder disbursements are `Active advance` inflows but not revenue; they are not repayments. Later reviewed labels must use this same function with the unchanged source amount.

The deliberately imperfect v1 baseline has concrete errors on synthetic intent: `SQUARE INC MERCHANT SETTLEMENT` matches both `square` and `merchant settlement`; `Active advance` wins over the true processor revenue intent. `UCC 1` misses literal `ucc-1`; `OD-FEE` misses `od fee`. A further literal collision is **`nsf` inside `transfer`**: `INTERNAL TRANSFER` matches both `NSFs` and `Internal transfer`, and `NSFs` wins. `NSF ATHLETICS` also looks like a fee to the keyword engine but is an ordinary synthetic uniform purchase. These are baseline errors for later review, not reasons to silently rewrite approved v1 rules. A description alone cannot verify an actual lien, bankruptcy, or payment failure.

Run `uv run --group dev pytest tests/test_legacy.py` for taxonomy, precedence, trace, revenue, and full 2,000-transaction labeling evidence. Synthetic truth is consulted **only in tests** that prove known errors; it is never an argument to `label_transaction` or `label_transactions`. No LLM, Plaid API, credit features, or offer calculation is performed here.
