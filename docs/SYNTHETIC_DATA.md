# Synthetic dataset v1 — scenario inventory

This inventory is the **scenario intent**, written before generating the fixtures. It is a project-designed test set, not real bank/customer evidence. The generator is `src/fundo_reviewer/synthetic.py`, version `synthetic-v1`, seed `20261008`, `as_of = 2026-10-08`. Regeneration uses only Python's standard library and the Ticket 01 validator.

| Scenario ID | Intended economic meaning and deliberate test |
| --- | --- |
| `processor_square` | `SQUARE INC` merchant settlement is business revenue, despite the funder-like word `SQUARE`; hard negative. |
| `processor_noisy` | Noisy `SQ *` / Shopify processor settlement is business revenue. |
| `customer_sale` | Customer ACH receipt is business revenue without a named keyword group (`unmatched`). |
| `ordinary_expense` | Routine operating debit, `unmatched`. |
| `tax_refund`, `insurance_payout` | Business non-sales credits: `Not average monthly revenue`. |
| `nsf_fee` | Observed bank NSF/returned-item fee: `NSFs`. |
| `overdraft_fee`, `overdraft_punctuation` | Observed overdraft fees, including `OD-FEE` punctuation miss: `Overdraft`. |
| `internal_in`, `internal_out` | Own-account transfers in both directions: `Internal transfer`, never sales. |
| `ucc_filing`, `ucc_punctuation` | Filing-related debit, including `UCC 1` punctuation miss: `UCC`. This describes the synthetic intent, not proof of an actual lien. |
| `advance_disbursement`, `advance_repayment` | `SQUARE CAPITAL`/other funder inflow versus business repayment debit: `Active advance`; disbursement is neither revenue nor a payment. |
| `auto_deposit` | Genuine customer direct deposit: `Auto deposit`, eligible revenue. |
| `revenue_verification` | Merchant settlement: `Revenue verification`, eligible revenue. |
| `gambling`, `bankruptcy`, `debt_settlement`, `garnishment`, `other_high_risk` | Debit examples for each of the five named high-risk groups. Descriptions alone do not verify legal/contract status; the intent is synthetic. |
| `personal_in`, `personal_out` | Owner/family activity; personal credits are not business revenue. |
| `capital_equipment` | Ordinary equipment purchase with `capital` in the text; `unmatched`, hard negative. |
| `nsf_name_collision` | Payment to synthetic `NSF Athletics` for team uniforms, not a bank fee; `unmatched`, hard negative. |
| `instruction_text` | Customer-controlled description contains an instruction-like string; it remains untrusted transaction data and ordinary business revenue. |
| `opaque_receipt` | Intended customer receipt, but description alone does not establish the counterparty; explicitly ambiguous. |

The 13 Fundo groups are represented by the `Not average monthly revenue`, `NSFs`, `Overdraft`, `Internal transfer`, `UCC`, `Active advance`, `Auto deposit`, `Revenue verification`, `High risk — gambling`, `High risk — bankruptcy`, `High risk — debt settlement payments`, `High risk — garnishment`, and `High risk — other` scenarios above. `unmatched` is an explicit non-group state.

`biz_01` has five observed NSF fees and `biz_02` has six, preserving the later offer-boundary exercise. `biz_10` is the no-fee-bank case: **zero observed NSF fees, unobserved failed-payment incidents unknown**, not a verified zero-risk case. `biz_09` and `biz_10` form a held-out business cohort for later final checks; do not tune rules/prompts against their truth. `biz_61` is a separate short-history cohort and is not part of the main accuracy denominator. A template can occur in both development and held-out businesses, so the holdout is by business rather than unseen template.

## Artifacts and regeneration

Run from the repository root:

```bash
PYTHONPATH=src uv run python -m fundo_reviewer.synthetic --output-root data
uv run --group dev pytest tests/test_synthetic.py
shasum -a 256 data/transactions/*.json data/ground_truth/*.json
git diff --exit-code -- data/transactions data/ground_truth
```

The command writes `data/transactions/main_90_days.json`, `data/ground_truth/main_90_days.json`, `data/transactions/short_61_days.json`, and `data/ground_truth/short_61_days.json` in fixed order with a trailing newline. The ground-truth files contain ID-keyed intent, rationales, ambiguity/hard-negative markers, and plausible alternative labels for later sensitivity simulations. They are **evaluation-only**: neither transactions nor a future reviewer request/cache key may contain them. The generator prints counts, signs, coverage and scenario counts, but no intended labels or rationales. Determinism tests compare committed file bytes against freshly generated bytes; the SHA-256 values printed by the command can also be compared.
